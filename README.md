# Система учёта заказов в небольшой пекарне

Учебный консольный проект на C++17: создание товаров через фабрику, расчёт стоимости корзины и печать чека. Демонстрирует инкапсуляцию, наследование, полиморфизм, владение ресурсами через `std::unique_ptr` и обработку исключений.

## Запуск в Visual Studio Code на этом компьютере

1. Откройте **папку проекта** `bakery-oop` через File → Open Folder.
2. Нажмите `Ctrl+Shift+B` — задача `Build bakery (GCC)` создаст `build/bakery.exe`.
3. Для запуска выберите Terminal → Run Task → `Run bakery`. Для отладки с точками останова нажмите `F5` и выберите `Debug bakery (GDB)`.

Настройки `.vscode` используют установленный GCC и GDB из `C:/msys64/ucrt64/bin`. На другом компьютере замените пути к инструментам в `tasks.json`, `launch.json` и `c_cpp_properties.json`. Рекомендуемые расширения: Microsoft C/C++ и CMake Tools. По умолчанию открывается интерактивное меню; сценарий из задания запускается с аргументом `--demo`.

## Интерактивное меню

1. Посмотреть каталог (при запуске есть три примера).
2. Создать свой хлеб, выпечку или торт: название, параметры и цены вводятся по подсказкам.
3. Удалить товар из каталога.
4. Добавить товар из каталога в корзину, указав номер и количество.
5. Посмотреть корзину и чек.
6. Изменить количество в строке корзины.
7. Удалить строку корзины.
0. Завершить работу.

Номера товаров и строк начинаются с 1 и обновляются после удаления. Дробные значения можно вводить с точкой или запятой. Некорректные данные выводят сообщение и возвращают в меню. Корзина получает независимую копию товара через виртуальный `clone()`, поэтому удаление из каталога сохраняет уже добавленные покупки. Данные хранятся в памяти до выхода из программы.

## Сборка без CMake (PowerShell, Windows/MSYS2)

Запускайте команды из корня проекта:

```powershell
$env:PATH = 'C:\msys64\ucrt64\bin;' + $env:PATH
New-Item -ItemType Directory -Force -Path build | Out-Null
$sources = @(
    'src/product.cpp', 'src/bread.cpp', 'src/pastry.cpp', 'src/cake.cpp',
    'src/order_item.cpp', 'src/cart.cpp', 'src/product_factory.cpp'
)
g++ -std=c++17 -Wall -Wextra -Wpedantic -g -Iinclude @sources src/console_app.cpp src/main.cpp -o build/bakery.exe
.\build\bakery.exe
# Демонстрационный сценарий из задания:
.\build\bakery.exe --demo
```

Для тестов в той же сессии PowerShell:

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic -Iinclude @sources tests/bakery_tests.cpp -o build/bakery_tests.exe
.\build\bakery_tests.exe
```

Ожидаемый результат: `PASS: 43 checks`. Проверяются формулы всех типов товаров, независимое полиморфное копирование, сеттеры, пересчёт количества, удаление, детали в чеке, пустая корзина, неизвестный тип, nullptr, неверные индексы, NaN, бесконечность и переполнение суммы. Проверки работают и при определённом `NDEBUG`.

Проверки меню в PowerShell после сборки приложения:

```powershell
& ./tests/console_tests.ps1
```

Проверяются создание всех трёх типов, добавление и удаление, сохранение корзины после удаления из каталога, изменение количества, ошибочный ввод, пустой каталог и корзина, конец ввода и режим `--demo`.

## Сборка через CMake

Требуется CMake 3.16+ и компилятор с C++17. На этом компьютере проверена прямая сборка GCC 15.2.0; CMake не установлен, поэтому этот способ здесь не запускался.

Для Linux/macOS либо настроенной среды разработки Windows:

```sh
cmake -S . -B build
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

Запуск на Linux/macOS: `./build/bakery`. На Windows с генератором Visual Studio: `.\build\Debug\bakery.exe`; с одноконфигурационным генератором: `.\build\bakery.exe`.

Если установлен CMake и Ninja и используется MSYS2 GCC, в PowerShell:

```powershell
$env:PATH = 'C:\msys64\ucrt64\bin;' + $env:PATH
cmake -S . -B build-cmake -G Ninja -DCMAKE_CXX_COMPILER=C:/msys64/ucrt64/bin/g++.exe
cmake --build build-cmake
ctest --test-dir build-cmake --output-on-failure
.\build-cmake\bakery.exe
```

## Классы и структура

| Класс | Назначение |
| --- | --- |
| `Product` | Абстрактный интерфейс `getPrice`, `getName`, `printDetails`; хранение и валидация названия и базовой цены; виртуальный деструктор |
| `Bread` | Тип теста и вес в кг; цена = цена за кг × вес |
| `Pastry` | Начинка и доплата за неё; цена = базовая цена + доплата |
| `Cake` | Количество слоёв, декор и его цена; цена = цена за слой × слои + цена декора |
| `OrderItem` | Владение товаром, количество и стоимость строки; `setQuantity` проверяет данные и пересчитывает сумму |
| `Cart` | Добавление, удаление и изменение количества, получение суммы и полиморфная печать чека |
| `ProductFactory` | Статический фабричный метод, возвращающий `std::unique_ptr<Product>` |

Заголовки находятся в `include/`, реализации и демонстрация — в `src/`, проверки — в `tests/`. `OrderItem` выделен в отдельные `.h/.cpp` для удобства. Меню и обработка ввода находятся в `console_app.cpp`; `main` выбирает интерактивный режим или демонстрацию. Все поля классов закрытые, чтение и изменение выполняются через методы. Методы чтения объявлены `const`.

## Фабрика и владение

Сигнатура:

```cpp
static std::unique_ptr<Product> createProduct(
    const std::string& type, const std::string& name, double basePrice,
    const std::string& detail, double value, int layers = 1);
```

| `type` | `basePrice` | `detail` | `value` | `layers` |
| --- | --- | --- | --- | --- |
| `bread` | Цена за кг | Тип теста | Вес в кг | Не используется |
| `pastry` | Базовая цена штуки | Начинка | Доплата за начинку | Не используется |
| `cake` | Цена за слой | Декор | Цена декора | Число слоёв |

Такая сигнатура позволяет выбирать тип строкой без `...` и небезопасных приведений. Фабрика выбирает класс, а конструкторы используют валидирующие сеттеры. Пример:

```cpp
Cart cart;
cart.addItem(ProductFactory::createProduct("bread", "Хлеб", 120, "ржаное", 0.5), 2);
cart.addItem(ProductFactory::createProduct("cake", "Торт", 300, "ягоды", 200, 3), 1);
cart.setItemQuantity(0, 3);
cart.removeItem(1);
cart.printReceipt();
```

`addItem` принимает владение товаром; при передаче именованного `unique_ptr` нужен `std::move`. После передачи товар редактировать через ранее сохранённые указатели нельзя: строка хранит рассчитанную стоимость. Через `getItem` доступен только `const` товар. Повторные добавления создают отдельные строки, индексы методов корзины начинаются с нуля, номера строк чека — с единицы.

Некорректные параметры вызывают `std::invalid_argument`, неверный индекс — `std::out_of_range`. Нулевые цены разрешены, нулевые вес, слои и количество запрещены. Неудачное изменение количества сохраняет прежнюю сумму. По условию используются `double`; форматирование до двух знаков выполняется при печати.

## Пример вывода

Начальный чек демонстрации (`bakery --demo`):

```text
=== Чек пекарни ===
1. Хлеб ржаной
   Тесто: ржаное, вес: 0.50 кг
   60.00 руб. x 2 = 120.00 руб.
2. Слойка
   Начинка: вишня
   80.00 руб. x 3 = 240.00 руб.
3. Торт праздничный
   Слоёв: 3, декор: ягоды
   1100.00 руб. x 1 = 1100.00 руб.
Итого: 1460.00 руб.
```

Затем программа выводит сообщения об ошибках и продолжает работу:

```text
Проверка некорректного количества:
Ошибка: Количество товара должно быть больше нуля.

Проверка некорректного товара:
Ошибка: Вес хлеба должен быть конечным числом больше нуля.

Проверка неизвестного типа:
Ошибка: Неизвестный тип товара: pizza
```

После смены количества слоек с 3 на 2 печатается новый чек с итогом `1380.00 руб.`. Затем удаляется торт, остаются две строки. Последняя проверка:

```text
Проверка пустой корзины:
Корзина пуста. Добавьте товары для формирования чека.
```

## Git

Репозиторий содержит пять отдельных коммитов по этапам исходного задания:

1. Структура проекта.
2. Реализация Product и наследников.
3. Реализация Cart и фабрики.
4. Обработка ошибок и main.
5. README и сборка, настройки VS Code и проверки.

Интерактивное меню добавлено отдельным следующим коммитом.

Репозиторий: https://github.com/jenja251/OOP. Базовая ветка `main` содержит начальный пустой коммит; реализация находится в `develop` для проверки через PR в `main`. Просмотр этапов: `git log --oneline --reverse main..develop`. Каталоги сборки, бинарные и временные файлы исключены из Git. Четыре общих файла настроек VS Code сохранены для воспроизводимой сборки, остальные файлы IDE игнорируются.
